TECHNICAL / USER GUIDE

每份报价，都有依据。

选题：RFQ询价分析与报价智能体。目标客户为工业零部件经销商、销售报价团队与采购人员。作品围绕“客户修改数量，旧报价受到什么影响”呈现可追溯闭环。

架构与技术栈

浏览器工作台 → FastAPI权限与业务接口 → SQLite业务数据及原件 → 确定性Decimal成本引擎 → 双角色审批 → PDF/Excel导出。Genesis作为可替换服务端提取适配器；MatrixOne作为审批报价的应用层镜像，不替代主数据库。

Python、FastAPI、SQLite、Pydantic、PyMuPDF、openpyxl、原生JavaScript。模型API Key仅在服务端环境变量配置，浏览器和文档不包含密钥。

创新点

  • 版本差异与报价影响关联：数量变化定位到旧报价，保留已审批快照，重新核价和审批。
  • 字段级原文证据与修改历史：模型建议、规则提取、人工修订分别记录。
  • 透明核算：明确区分毛利率和加价率，展示成本构成、运费分摊及按分舍入口径。

实际使用步骤

  1. 管理员上传合成RFQ。规则不能识别时，主动触发Genesis补充提取。
  2. 查看模型输入、真实响应编号、原文证据与来源；人工核对描述和字段后确认入库。
  3. 上传供应商原件，采用规则提取候选字段，人工确认后参与报价。
  4. 比较三方案；复核员审核，管理员独立审批，再导出PDF/Excel。
  5. 客户更新数量时登记新版本，比较影响，复核新需求，重新计算并完成新审批。
