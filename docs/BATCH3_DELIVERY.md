接续第二批 GitHub 提交 1b6bf59；独立 commercial-upgrades 分支，现网与登录部署保持暂停。

已实现：

- 同客户来源邮箱标识 + RFQ号建立版本系列；实际导入行生成不可变快照，保存附件ID/摘要、登记人、原因、时间及快照SHA256。
- 对任意两个同系列历史版本比较型号、描述/规格、数量、单位、件状、询价截止日期和MPN；稳定客户行号优先，其次唯一件号，拒绝按行序强配。
- 重复件号无稳定标识时进入待人工匹配；页面支持录入实际旧/新行ID和依据，追加保存人工决策后重新计算，不覆盖先前决策。
- 新增、删除、修改、不受影响、待确认分类；对原报价关联检查需要重新核价/询供应商、MOQ、报价有效期及潜在交期/利润影响。不凭空计算新供应商价或利润。
- 交付日期/地点、付款条件、特殊要求支持带文件ID、人工定位、原文的人工条款录入；未提供保持未知，不把询价截止日当作交付日期。
- 新版本差异页面具备高亮、删除线、前后值、附件变化及关联报价风险。原版本、原报价快照保持不变。

实测：

- 7个版本测试通过：至少5组实际合成版本，覆盖数量100→500与过期报价影响、重排/增删/不受影响、稳定行号下型号改变、重复件号歧义与人工确认、单位/规格/件状及条款、跨客户拒绝，以及完整API登记/读回/差异。
- 核心回归197 passed（14个模块），1条第三方弃用警告。
- 差异页面6条DOM断言通过，含XSS转义、前后值高亮、待匹配表单和未知交付条款；非公网浏览器验收。
- 无外部API/模型调用，无模拟平台执行ID，未部署或修改线上数据。

限制：

- 客户标识来自邮件记录，不是已核验供应商/客户身份；缺少地址拒绝自动合并。原RFQ号不同的更新不自动猜测为同系列。

- 来源页码/单元格证据沿用第二批；扫描件仍需人工。
